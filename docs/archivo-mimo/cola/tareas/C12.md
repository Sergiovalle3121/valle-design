# C12 · ETRANSMIT empaqueta lo que el cliente puede abrir

**Frente:** entregable   **Esfuerzo:** varias-sesiones
**Fichero:** `apps/web/src/lib/cad/etransmit/etransmit.ts:144`

## Por que importa al arquitecto
El paquete de entrega lleva hoy un `.json` que sólo VALLECAD lee. Un eTransmit de AutoCAD lleva DWG abribles; éste no lleva ni PDF ni DXF, así que mandarlo es mandar nada.

## Que hacer
TÍTULO: ETRANSMIT mete en el paquete el DXF, y lo prueba reimportándolo

DÓNDE: `apps/web/src/lib/cad/etransmit/etransmit.ts` (input y manifiesto) y `apps/web/src/lib/cad/engine/commands/etransmit-commands.ts:137` (la llamada real). NO se toca `etransmit-host.ts` ni `host-requests.ts`.

QUÉ HACER
1. `etransmit.ts`: añadir `dxf?: { fileName: string; bytes: Uint8Array }` a `BuildCadTransmittalPackageInput` y `"interchange"` a `CadTransmittalManifestEntry.kind`. Si viene, entra al zip por `dedupedPath("intercambio", fileName)` —la función ya existe, líneas 158-168— y se declara en `entries` con `included: true` y su `path`. Si no viene, una entrada `included: false` con `reason`, igual que xrefs e imágenes.
2. NO añadir `pdfs?`. Hoy ningún llamador puede poblarlo (el PDF es asíncrono y el anfitrión recibe el zip ya hecho), y un parámetro opcional que nadie rellena es exactamente el patrón «declarado y no hace nada» que las revisiones anteriores encontraron.
3. `etransmit-commands.ts`, dentro de `pack()`: llamar `exportCadDocumentDxf(fullDocument)` —síncrona y pura, `dxf-document-export.ts:127`, mismo uso que DXFOUT en `interop-dxf.ts:350`— y pasar `dxf: { fileName: `${name}.dxf`, bytes: new TextEncoder().encode(exportado.content) }`. Las `losses` que devuelve NO se tiran: se añaden al `reason` de la entrada o a `omittedSections`, para no fingir que el DXF lleva todo el dibujo (el exportador ya declara que excluye espacio papel).

TERMINADO CUANDO, todo dentro de `apps/web/src/lib/cad/engine/commands/etransmit-commands.spec.ts`, que ya conduce el descriptor real:
- Caso positivo: documento limpio (sin hallazgos que bloqueen, como el caso «plano limpio» que el spec ya monta) con geometría conocida y fija: dos líneas y un círculo de centro y radio literales. Se teclea el comando, se toma `request.bytes` del `result.kind === "host"` y se lee el zip con el lector independiente de `zip-writer.spec.ts:28-55` (duplicarlo o extraerlo a un helper; nunca importando `buildZip`).
- Existe la ruta `intercambio/<nombre>.dxf`, y su texto pasado por `importDxfPrimitives` (`apps/web/src/lib/cad/dxf-import.ts:821` — el parser real, que no comparte código con el escritor) devuelve el mismo número de entidades y el centro y el radio del círculo con tolerancia 1e-9. PROHIBIDO afirmar sólo «los bytes de salida son los de entrada»: eso reprueba `buildZip`, ya probado.
- `manifiesto.json`, leído DEL PROPIO ZIP y parseado, lista esa entrada con `included: true` y con el mismo `path` que se encontró en el zip.
- Caso negativo: un documento sin entidades exportables a DXF → la entrada del manifiesto va `included: false` con su motivo y en el zip no hay ninguna ruta bajo `intercambio/`.

TAREA SEPARADA, para proponer aparte y no aquí: para que viaje un PDF hay que cambiar primero la petición `{ kind: "etransmit" }` de `host-requests.ts` para que lleve el manifiesto y las entradas en vez de bytes cerrados, y que el anfitrión rearme el zip tras `await renderCadPlotPdf(...)` usando el `CadPlotHost` que `use-command-engine.ts` ya construye. Es un commit propio y cambia una frontera; no se cuela dentro de éste.

## Terminado cuando
Spec que llama a `buildCadTransmittalPackage` con un DXF y dos PDF de bytes conocidos y afirma, LEYENDO el zip emitido con el lector de `zip-writer.spec.ts`: existen las rutas `intercambio/plano.dxf`, `pdf/A-101.pdf` y `pdf/A-102.pdf`, sus bytes coinciden byte a byte con los de entrada, y el manifiesto las lista con `included: true`. Segundo caso: sin aportarlas, el manifiesto declara las tres como `included: false` con su motivo y el zip no las contiene. Tercero, por el anfitrión real: ejecutar el comando `ETRANSMIT` del motor con el puente de `etransmit-host.ts` y afirmar que el zip descargado lleva un `.dxf` y un `.pdf`.
