# C23 · ROTATE3D resuelve a 3DROTATE

**Frente:** transformar-visualizar   **Esfuerzo:** una-sesion
**Fichero:** `apps/web/src/lib/cad/engine/alias-table.ts:284`

## Por que importa al arquitecto
ROTATE3D fue el nombre en AutoCAD hasta 2007 y sigue siendo lo que teclea un veterano; hoy no resuelve a nada y el producto se siente ajeno por una línea que falta.

## Que hacer
TÍTULO: Los alias 3D de acad.pgp (3R, 3M) y el heredado ROTATE3D llegan a la línea de comandos

POR QUÉ IMPORTA: `3R` y `3M` son las filas de acad.pgp para 3DROTATE y 3DMOVE, y hoy teclearlas devuelve «Comando desconocido». El comentario de alias-table.ts:277-281 ya diagnosticó esta clase de fallo tecleando `3DZ`; el bloque de transformación 3D se quedó sin barrer. ROTATE3D va de paso porque es el nombre con el que un veterano gira un sólido desde la línea.

DÓNDE (tres ficheros, ninguno generado):
- `apps/web/src/lib/cad/engine/commands/transform-3d-rotate.ts:250` — `aliases: ["3R"]` → `aliases: ["3R", "ROTATE3D"]`. NO tocar command-manifest.ts a mano: es generado.
- `apps/web/src/lib/cad/engine/alias-table.ts:281` — abrir un bloque «transformación 3D» justo antes del de navegación 3D con exactamente tres filas: `"3R": "3DROTATE"`, `"3M": "3DMOVE"`, `ROTATE3D: "3DROTATE"`. Ninguna más: no inventar alias para comandos que no están en el manifiesto, porque `index.spec.ts:182-191` exige `unresolvedAliases().length === 0` y un alias huérfano rompe el gate.
- `apps/web/src/lib/cad/engine/command-engine.spec.ts` — las aserciones.

QUÉ HACER DESPUÉS: `npm run build:command-manifest` (regenera la entrada 3DROTATE del manifiesto desde el descriptor) y `npm run check:command-manifest` para confirmar cero diferencias.

TERMINADO CUANDO (todo contra el motor real, nada redefinido en el spec):
1. En `command-engine.spec.ts`, con el registro REAL del producto (`createCadCommandRegistry(CAD_COMMAND_DESCRIPTORS)`, como ya hace ese fichero) y su `registry.names()` pasado como segundo argumento — NO la llamada de un solo argumento, que devuelve el token normalizado para cualquier cosa y no prueba nada:
   - `resolveCadCommandAlias("3R", registry.names()) === "3DROTATE"`
   - `resolveCadCommandAlias("3M", registry.names()) === "3DMOVE"`
   - `resolveCadCommandAlias("ROTATE3D", registry.names()) === "3DROTATE"`
   - `resolveCadCommandAlias("_rotate3d", registry.names()) === "3DROTATE"`
2. Por el PIPELINE, no por la tabla: `resolveCadToken("3R", { knownCommands: registry.names() })` devuelve `{ kind: "invoke", command: "3DROTATE" }` — y lo mismo para `3M` y `ROTATE3D`. Antes de este cambio esa misma aserción da `{ kind: "error", message: 'Comando desconocido "3R".' }`, así que el spec falla si se revierte la tabla.
3. `registry.get("3R")` y `registry.get("ROTATE3D")` devuelven un descriptor cuyo `.name === "3DROTATE"`.
4. Aserción de no-regresión de la clase entera, que es lo que evita el siguiente `3DZ`: para TODO alias declarado en cualquier `aliases` de `CAD_COMMAND_MANIFEST`, existe `CAD_COMMAND_ALIASES[alias]` o el alias está en `registry.names()`; el fallo imprime la lista de alias mudos. Es la dirección que `registry.unresolvedAliases()` NO cubre (solo mira tabla→comando). Si esa aserción revela más alias mudos aparte de 3R/3M, se listan en el mensaje y se dejan para su propia tarea: NO se añaden a la tabla en este commit.
5. `npm run check:command-manifest` pasa sin diferencias.

NO INCLUYE: tocar umbrales, presupuestos ni la aserción `pending.length === 0` de index.spec.ts.

Aserción en apps/web/src/lib/cad/engine/command-engine.spec.ts de que resolveCadCommandAlias('ROTATE3D') devuelve '3DROTATE' y que '_rotate3d' (prefijo internacional) también. `npm run check:command-manifest` pasa sin diferencias.
